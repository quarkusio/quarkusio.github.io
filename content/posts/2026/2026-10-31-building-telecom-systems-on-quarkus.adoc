= Introducing micro-jainslee: JAIN SLEE for Quarkus and Java 25

micro-jainslee is a lightweight, embeddable implementation of the JAIN SLEE 1.1 (JSR 240) programming model, built for Java 25 and modern telecom applications.

JAIN SLEE provides an event-driven programming model for telecom services that require high throughput, asynchronous processing, stateful sessions, and integration with network protocols. Its Service Building Blocks (SBBs), events, activities, and Resource Adaptors (RAs) separate service logic from network integration.

Built for Java 25 and integrated with Quarkus, micro-jainslee embeds the SLEE runtime directly into an application without requiring a separate JBoss or WildFly application server.

== How it works

Each Resource Adaptor exposes three ports that define its interaction with the runtime:

[cols="1,2,2,3", options="header"]
|===
|# |Port role |Interface |Direction / Operation

|1
|Lifecycle
|`RaEndpointPort`
|Container → RA (`activate` / `deactivate`)

|2
|Commands
|`RaCommandPort`
|SBB → RA (`sendCommand`)

|3
|Events
|`RaBootstrapPort`
|RA → SLEE (`fireEvent`)
|===

The runtime uses Java 25 Virtual Threads for concurrent execution and the LMAX Disruptor as its event-routing backbone. This provides a lightweight foundation for handling large numbers of independent telecom sessions.

Optional clustering support is also available through the clustering module.

== Built for telecom workloads

I am using micro-jainslee as a common foundation for telecom systems that I am actively developing, including USSD gateways and services, SMSC, GMLC, and 4G Core components.

These systems share common requirements: asynchronous event processing, session management, and reliable integration across different network protocols.

The repository includes Quarkus-based USSD and SIP gateway examples, together with Resource Adaptors for HTTP, SIP, Diameter, and gRPC.
